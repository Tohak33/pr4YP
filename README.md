# Мебельный магазин

Информационная система продажи мебели на React, Express и PostgreSQL.

## Запуск

Требуются Node.js и PostgreSQL. Сервер использует подключение к базе данных из `backend/.env`. Схема и начальные товары уже находятся в этой базе.

```powershell
cd backend
npm install
npm start
```

Сервер запускается на порту 5000 и проверяет подключение к базе данных.
При запуске он добавляет в существующую таблицу купонов поля для однократного использования и связи с заказом.

В другом терминале:

```powershell
npm install
npm run dev
```

Клиент: `http://localhost:5173`. Адрес API по умолчанию `http://localhost:5000/api`; для другого адреса задайте `VITE_API_URL`.

## Проверка ролей

Новые учётные записи получают роль `customer`. Для учебной проверки администратора зарегистрируйте отдельную учётную запись, затем назначьте роль в PostgreSQL:

```sql
UPDATE users SET role_id = (SELECT id FROM roles WHERE name = 'admin')
WHERE email = 'admin@example.com';
```

Выйдите и войдите снова. В панели администратора доступны товары, категории, заказы и отзывы. Изменение и удаление пользователей или чеков не предусмотрено.
Администратор видит список покупателей, может выдавать каждому персональные купоны со скидкой 1–99% и отзывать неиспользованные купоны.

## Восстановление пароля

Для отправки письма укажите `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER` и `SMTP_PASSWORD` в `backend/.env`. `SMTP_FROM` необязателен: по умолчанию отправителем будет `SMTP_USER`. Без SMTP форма сообщает, что отправка не настроена. Каждый запрос создаёт новый шестизначный код на 10 минут; в БД хранится только его хэш.

## Правила заказа

- Корзина и сессии хранятся в PostgreSQL. После выхода товары остаются у того же пользователя.
- В одном заказе не более 10 единиц; на выбранную дату суммарно по всем категориям доступно 10 единиц.
- Дата доставки проверяется на клиенте и сервере. Товар с нулевой ценой заказать нельзя.
- Скидка должна быть как минимум у 30% товаров каталога; нужное количество округляется вверх. Сервер проверяет это правило при добавлении, изменении и удалении товара.
- Весь заказ получает один номер и одну итоговую сумму. При оформлении заказ и запись его оплаты сразу получают статус «Оплачено». Администратор может перевести заказ в доставку и завершение; вернуть оплаченный заказ к ожиданию оплаты нельзя.
- Скидка 5% применяется автоматически только к первому заказу пользователя.
- Персональный купон виден покупателю в личном кабинете и выбирается в корзине. Он действует на один заказ только владельца. Скидка по купону применяется после скидок на товары и скидки на первый заказ; использованный купон повторно применить нельзя.
- Покупатель может оставить один отзыв на товар после оплаты заказа с этим товаром, изменить свою оценку и текст или удалить свой отзыв. Пустые отзывы и распространённая ненормативная лексика отклоняются. После модерации отзыв остаётся с пометкой об удалении за нарушение политики; покупатель не может изменить или удалить эту отметку.
- Администратор может создавать и переименовывать категории. Удаление категории переносит её товары в «Без категории».
- Категории каталога получаются через JOIN с товарами мебели. Новые категории доступны сразу после создания.

## Проверка проекта

```powershell
npm run lint
npm run build
```

Фронтенд использует названия категорий, коды товаров и номера заказов; связи между таблицами строит сервер через SQL JOIN. Сервер проверяет сессию и роль на каждом защищённом маршруте.
